# 工程导航

## 控制链路

网页 `studio/web-vue` → `services/studio_gateway` → `services/inspection_control` → `services/rvclaw_voice` 的任务队列/启动器 → K1 mission route → Nav2 → `rvclaw_stm32_base` → STM32 底盘。

人工语音从 `services/rvclaw_voice/vendor_m2_command_adapter.py` 进入同一任务执行链。网页进度由 `services/inspection_progress` 被动观察任务和到点事件，网关提供历史轨迹、地图与识别结果。浏览器构建文件由 Python 网关提供，板端不运行 Node 开发服务器。

## 定位与运动

- 底盘协议、轮速反馈、里程计、控制门限：`robot/ros2_ws/src/rvclaw_stm32_base`。
- 雷达驱动：`robot/ros2_ws/src` 中的 lidar 包；设备规则在 `deploy/k1/udev`。
- 导航及建图公共包：`robot/ros2_ws/src/rvclaw_nav2_bringup`。
- 实际导航配置与覆盖模块：`robot/profiles/navigation/overrides`。
- K1 任务执行器、连续导航、转向和静止定位：`deploy/k1/compatibility`。
- 原生 AMCL：`deploy/k1/native/amcl`；扫描匹配内核：`deploy/k1/compatibility/scan_map_kernel.c`。
- 场地地图、点位、检测方向及阈值：`configs/scenes/inspection-k1-reviewed`；初始地图选择：`deploy/k1/snapshot/inspection-profile.json`。

`deploy/k1/snapshot/source-layout.json` 记录运行文件到源码入口的对应关系与 SHA256。源码覆盖层只保存构建输入，`ros2_ws/build`、`install` 及组装出的工作区不进入 Git。

## 识别与语音

- 数字/指针仪表及服务：`services/meter_gauge`、`services/rvclaw_api`、`robot/ros2_ws/src/rvclaw_algo`。
- 首次本地失败后本地与云端并行：`services/meter_gauge/meter_gauge/hybrid.py`；说明见 `services/meter_gauge/CLOUD_METER.md`。
- 仪表参考图及配置：`configs/device/meter`；模型路径：`configs/device/vision`。
- 语音硬件协议与调度：`services/rvclaw_voice`；SenseVoice/VAD 和原音色提示音由资源包恢复。
- RGB 辅助与深度接口：`configs/perception` 及相关 ROS2 源码。Astra Pro 的 K1 深度流尚未完成可用性验证，不能宣称深度定位已启用。

## 调度与网页

`deploy/k1/runtime_demand.py` 按设备及任务需求管理导航。核心分配、优先级、资源限制和设备等待配置保存在 `deploy/k1/snapshot/systemd-user`，复制自当前实际配置，没有重新调参。

网页任务/进度约定见 `contracts/studio-patrol-live.md` 及同目录其他文件。各模块按现有产品目录存放，临时测试工具不进入业务目录。
